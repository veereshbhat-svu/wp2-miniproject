Problem Statement

Design and implement a scalable, regulation-aligned backend service for UrineScan built with Node.js, Express.js, and MongoDB (via Mongoose ODM), that transitions the platform from a simulated client-side prototype to a persistent, clinical-grade Point-of-Care (POC) diagnostic engine. The backend replaces static mock data and ephemeral localStorage with a robust multi-collection MongoDB database, implements an on-device computer vision colorimetry algorithm that extracts and quantifies real RGB pixel data from uploaded 10-pad reagent strips, provides an automated clinical decision-support engine that correlates chemical analytes with triage symptoms, generates cryptographically verified scannable QR codes for smartphone verification across the hospital LAN, streams real-time sensor telemetry via Server-Sent Events (SSE), and produces official hospital-branded diagnostic PDF reports.

The purpose of the backend is to establish an end-to-end medical data pipeline for hospital pathology departments (modeled after K. J. Somaiya Hospital & Research Center). It ensures that every urinalysis test is strictly associated with a verified patient record, automatically classifies multi-condition risks (such as Acute Bacterial UTI, Glomerular Nephropathy, and Diabetic Ketoacidosis), prevents data tampering via SHA-256 cryptographic integrity hashes, and facilitates interoperability through simulated HL7/FHIR v4 transmissions to hospital Health Information Systems (HIS).

Scenario

A lab technician opens UrineScan and lands on the consolidated Point-of-Care Dashboard. When entering a new clinical triage intake, the patient’s clinical presentation, temperature, duration, and symptom chips are sent to the backend via POST /api/triage/submit. The server evaluates the presentation via an algorithmic NLP classification engine, stores the persistent Triage document in MongoDB, and suggests an appropriate clinical profile with risk levels and guidance.

Moving to the Analysis stage, the technician can upload an actual photo of a 10-pad urine strip. The backend's Colorimetry Vision Engine (built on Jimp) slices the strip geometry into 10 reagent zones, computes center ROI average RGB vectors, and maps them against standard Multistix 10-SG calibration curves using Euclidean color distance. Concurrently, the Clinical Decision Support Engine evaluates multi-analyte cross-interactions (such as Nitrite + Leukocytes for UTI, or Protein + Specific Gravity for Renal Glomerular Strain).

The backend computes a SHA-256 integrity hash, generates a mobile-scannable QR code linking to http://<LAN-IP>:5000/verify/:reportId, and commits the records atomically into MongoDB. Pathologists can stream live telemetry, download official hospital-branded PDF lab reports, or scan the on-screen QR code from any smartphone to verify the certificate against live hospital database records.

Functional Requirements

1. Urinalysis Report & Clinical Intelligence Service (/api/reports)

Architecture
  • Implemented in controllers/reportController.js and mounted on routes/reportRoutes.js.
  • Handles complete report lifecycle, cryptographic hashing, QR synthesis, and clinical risk evaluation.
REST Endpoints
  • GET /api/reports: Paginated list with filtering by status (Normal, Warning, Abnormal) and text search (patient name, patient ID, report ID).
  • GET /api/reports/:id: Retrieves single report by reportId or ObjectId, auto-generating QR code if missing.
  • POST /api/reports: Persists a newly generated urinalysis report, evaluates clinical risk indices, hashes payload, and links to Patient.
  • DELETE /api/reports/:id: Deletes a test record from MongoDB.
  • DELETE /api/reports/clear-all: Clears all reports for dashboard reset.
Mongoose Schema
  • models/Report.js: includes reportId (indexed), patient (ObjectId ref to Patient), patientId, patientName, status, clinicalNote, analytes (array of 10 items with exact value, unit, reference interval, status, and hex color), clinicalRisk, verificationHash, qrCodeDataUrl, and hisSync.
Clinical Decision Support
  • UTI Probability (0–100%): Nitrite (+) [40 pts], Leukocytes abnormal [35 pts], Hematuria [10 pts], alkaline pH [10 pts], plus Dysuria/Fever symptoms.
  • Renal Strain (0–100%): Proteinuria [50 pts], high Specific Gravity ≥ 1.028 [15 pts], Blood [20 pts], and Flank/Back pain.
  • DKA Risk (0–100%): Glycosuria > 100 mg/dL [50 pts], Ketonuria > 15 mg/dL [40 pts], and Polyuria/Thirst.
  • Auto-generates pathophysiological findings and physician clinical guidance.
Security & Verification
  • 256-bit cryptographic digest using crypto.createHash('sha256') across reportId, patientId, analytes, and date.
  • High-contrast QR code data URLs generated via qrcode embedding LAN verification links.
PDF Generation
  • GET /api/reports/:id/pdf pipes dynamic pdfkit stream with hospital branding, patient details, styled 10-analyte table, risk dials, QR code, and digital pathologist signature lines.
HIS Integration
  • POST /api/reports/:id/send-his simulates encrypted HL7 FHIR v4 transmission with transaction IDs (HL7-TX-...) and MongoDB audit timestamps.

2. True-Vision Colorimetric Strip Processing (/api/reports/analyze-strip)

Architecture
  • Implemented in utils/colorimetryEngine.js and exposed via POST /api/reports/analyze-strip.
  • Replaces client-side timer simulation with real image pixel sampling.
Image Uploads
  • Configured with multer disk storage (up to 10MB) for uploaded strip photos, or parses base64-encoded camera snapshots.
Computer Vision
  • Loads images via Jimp.read(), detects vertical vs. horizontal orientation, and slices strip into 10 equidistant pad zones with center 50% ROI cropping.
Color Extraction
  • Iterates across center ROI pixels to compute true mean RGB vectors [avgR, avgG, avgB] and CSS hex colors (#rrggbb).
Color Calibration
  • Calculates perception-weighted Euclidean color distance: sqrt(2*ΔR² + 4*ΔG² + 3*ΔB²) against Multistix 10-SG calibration reference tiers.
  • Maps each pad to continuous numerical concentration, reference interval, and clinical flag.
SSE Telemetry
  • GET /api/reports/stream-telemetry opens a live HTTP text/event-stream connection streaming calibration and segmentation progress directly to the frontend.

3. Patient Management & Longitudinal Analytics (/api/patients, /api/analytics)

Architecture
  • Modularized across controllers/patientController.js, controllers/analyticsController.js, and controllers/verifyController.js.
REST Endpoints
  • GET /api/patients: Lists registered patients with report counts and latest screening status.
  • GET /api/patients/:id: Retrieves patient profile and time-series arrays for Recharts line graphs.
  • POST /api/patients: Registers or updates patient demographics.
  • GET /api/analytics/dashboard: Computes real-time dashboard KPIs.
  • GET /verify/:id: Public mobile verification web portal.
Aggregation Pipeline
  • Uses MongoDB $group and $sum stages on the Report collection to compute total tests, normal scans, flagged scans, and testing volumes atomically.
Mobile Verification
  • Public verification route /verify/:id renders a mobile-responsive hospital verification badge accessible by scanning the QR code with any smartphone camera on the local network.
